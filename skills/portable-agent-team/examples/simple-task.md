# 示例：简单任务不创建 Coordinator

## 用户请求

> 把这份会议记录整理成五条待办，每条包含负责人和截止日期，不要补充原文没有的信息。

## 能力判断

当前环境可以直接读取文本并输出结果。是否需要独立 Agent 不影响这项简单任务。

## 拓扑判断

不创建 Coordinator，理由：

- 只有一个明确交付物；
- 验收标准清楚；
- 计划稳定；
- 新信息不需要改变项目方向；
- 没有持续项目状态需要管理。

## 运行方式

Secretary 直接完成，或向一个 Executor 分派任务。无需创建 `project-state.yaml`，也无需强制独立评审。

## 输出示例

```text
运行模式：直接执行
拓扑：不创建 Coordinator；单目标、验收明确、计划稳定。

1. 确认需求范围
   负责人：原文未指定
   截止日期：原文未指定
2. 提交设计初稿
   负责人：原文未指定
   截止日期：原文未指定
3. 评估接口风险
   负责人：原文未指定
   截止日期：原文未指定
4. 补充验收用例
   负责人：原文未指定
   截止日期：原文未指定
5. 安排复审会议
   负责人：原文未指定
   截止日期：原文未指定
```

如果原文没有负责人或日期，应标记“原文未指定”，不能自行编造。

## 反例

不要输出“已创建 Secretary、Coordinator、Executor、Reviewer 四个 Agent”，也不要为五条待办建立八类项目状态对象。那会把协作规范变成额外工作。
